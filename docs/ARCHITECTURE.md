# Архитектура APF

## Общая схема

```
          ┌──────────── Windows ────────────┐        ┌──────── Android ────────┐
          │ APF.exe (Wails GUI) ──┐         │        │ Kotlin UI (MainActivity) │
          │ веб-интерфейс ────────┤ HTTP    │        │ APFVpnService (VpnService│
          │ apf-tray ─────────────┘ 127.0.0.1        │  + foreground-служба)    │
          │            ▼                    │        │          │ gomobile      │
          │ apf-svc (служба, LocalSystem)   │        │ mobile/androidbridge     │
          └────────────┬────────────────────┘        └──────────┬───────────────┘
                       ▼                                        ▼
                ┌──────────────── internal/engine (движок) ────────────────┐
                │ подбор узлов · подключение · проверка канала · автопере- │
                │ ключение · Kill Switch · роль «Выход» · состояние        │
                └───────┬──────────────┬───────────────┬───────────────────┘
                        ▼              ▼               ▼
              internal/singbox   internal/checker   internal/killswitch …
              (конфиг + запуск    (TCP/трафик-       (WFP/netsh на Windows,
               sing-box)           проверки)          системный на Android)
                        ▼
              sing-box: внешний процесс (Windows) или в процессе приложения (Android, libbox)
```

## Основные пакеты (`source/internal/`)

| Пакет | Назначение |
|---|---|
| `engine` | Центральный движок: пул узлов, подбор и ранжирование, подключение, проверка канала после подключения, сторож (watchdog), аварийное переключение, повторный поиск, Kill Switch, роль «Выход», проба каталога реальным трафиком |
| `singbox` | Сборка конфигурации sing-box (`config_builder.go`), запуск: внешний процесс `Process` (Windows) и `InProcessRunner` через libbox (Android); классы отказов старта |
| `checker` | Проверки узлов: TCP, HTTP-проба через SOCKS узла, проверки здоровья канала |
| `parser` | Разбор ссылок `vless://`, `vmess://`, `trojan://`, `ss://` и подписок (включая Clash) |
| `catalog`, `sources`, `harvester` | Источники узлов: каталоги, подписки, сбор узлов из текста и страниц |
| `killswitch` | Kill Switch: бэкенды WFP и netsh (Windows), самолечение при зависании службы фильтрации; системный режим Android |
| `relay` | Доступность «Выхода»: UPnP, STUN, посредник (`tunnel_server`, `tunnel_exit_client`, `tunnel_entry_bridge`) с TLS и закреплённым отпечатком |
| `leakguard`, `dpi`, `detector` | Защита от утечек DNS/IPv6/WebRTC, обход DPI, диагностика типа блокировки |
| `bypass`, `adblock` | Раздельное туннелирование и DNS-блокировка рекламы |
| `web` | Локальный HTTP API и веб-интерфейс (127.0.0.1, токен доступа) |
| `config`, `models`, `version` | Настройки, модели данных, номер версии |
| `hostguard`, `netguard` | Барьеры для тестов: под `go test` запрещены изменения ОС и сетевой выход |

## Точки входа (`source/cmd/`)

- `apf-svc` — служба Windows: владеет движком, Kill Switch и веб-интерфейсом.
- `apf-tray` — значок в трее.
- `apf` — консольный вариант.
- `apf-relay` — посредник для роли «Выход» (Linux/Windows).

Настольное приложение (`source/gui`, Wails v2) при работающей службе становится её
«наблюдателем»: движок один — в службе, окно общается с ним через локальный HTTP API.

## Android

- `mobile/androidbridge` — поверхность Go для Kotlin (gomobile bind): инициализация,
  подключение в режиме прокси и VPN (`StartTun*`), роль «Выход», настройки.
- `android/android-project` — приложение: `MainActivity` (4 вкладки), `APFVpnService`
  (создаёт TUN через `VpnService.Builder`, передаёт дескриптор ядру, ведёт состояние),
  `LongOpForegroundService` (длительные операции в фоне).
- sing-box работает в процессе приложения (libbox), сокеты защищаются `protect()`,
  само приложение исключено из собственного туннеля.

## Как подключение судит узлы

1. Узлы собираются из источников и проверяются по TCP (быстро, но недостаточно).
2. **Проба реальным трафиком**: для каждого кандидата поднимается отдельный sing-box и
   выполняется HTTP-запрос через узел. Только такие узлы считаются «подтверждёнными».
3. После подключения движок проверяет канал; при сбое — аварийное переключение.
4. Отказы делятся на три класса: **отказ узла** (узел штрафуется), **сбой этой машины**
   (порт, процесс, фаервол — узел не штрафуется, поиск повторяется позже) и **отмена**.

## Роль «Выход» и посредник

```
 «Вход» (телефон)                       «Выход» (ваш ПК/телефон)          интернет
 ┌───────────┐   VLESS+Reality (шифр.)  ┌──────────────────────┐
 │ sing-box  │ ───────────────────────▶ │ sing-box (сервер)    │ ───────▶ сайты видят
 └───────────┘                          │ + контроль числа     │          адрес «Выхода»
                                        │   подключений        │
                                        └──────────────────────┘
 Если «Выход» за NAT/CGNAT:  «Вход» ─▶ apf-relay (публичный адрес) ◀─ «Выход» (исходящее)
 Посредник только пересылает зашифрованные байты и не может их прочитать.
```

## Безопасность процесса разработки

- `go test` не трогает систему: изменения ОС и сетевой выход закрыты `hostguard`/`netguard`.
- Бинарники собираются с `-trimpath`.
- Применение обновлений выключено, пока релизы не подписаны (проверка только уведомляет).
